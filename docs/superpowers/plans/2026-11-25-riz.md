# Riz Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Riz, a local Windows desktop AI agent: a LangGraph agent on Ollama, file and command tools gated by approval cards, chat history, memory, a usage dashboard, and a tray-and-hotkey window.

**Architecture:** One Python process runs a FastAPI server on `127.0.0.1` (REST plus a WebSocket for streaming), the LangGraph agent with a SQLite checkpointer, a pywebview window showing the React UI, a tray icon and a global hotkey. Each tool that touches the system pauses the graph with `interrupt()` until the UI sends a decision. Every model call and tool call is logged to SQLite for the dashboard.

**Tech Stack:** Python 3.12, LangGraph 1.2, langgraph-checkpoint-sqlite 3.1, langchain-ollama 1.2, FastAPI, uvicorn, httpx, send2trash, pywebview, pystray, keyboard, pytest. React + TypeScript + Vite + Tailwind + shadcn/ui, react-markdown, rehype-highlight, recharts, lucide-react, @fontsource (Inter, JetBrains Mono), Vitest + Testing Library.

**Spec:** `docs/spec.md`. Mockups: https://claude.ai/artifact/Fqrddntqwhg88po5qGQTum

## Global Constraints

- Everything local: the server binds `127.0.0.1` only. No network calls except to Ollama at `http://127.0.0.1:11434`. Fonts are bundled through @fontsource, never Google Fonts.
- Approval policy is exactly: `recall_memory` and `save_memory` run freely; `read_file` asks with Allow / Deny / Pick another file…; `write_file`, `delete_file` and `run_command` ask with Allow / Deny.
- Deletes always go through `send2trash`. Nothing in Riz deletes a user file permanently.
- Limits: `READ_MAX_BYTES = 20_000`, `CMD_TIMEOUT_S = 60`, `CMD_MAX_CHARS = 10_000`, `num_ctx = 8192`, trim history to `6000` tokens before each model call.
- Qwen 3 thinking is off: the model is built with `reasoning=False`, and the runner strips any `<think>…</think>` text that still arrives. Token counts are logged as Ollama reports them (`output_tokens` = `eval_count`, which includes any thinking tokens).
- Default settings: `model="qwen3:8b"`, `theme="system"`, `hotkey="ctrl+space"`, `start_with_windows="true"`.
- Data lives in `RIZ_DATA_DIR` if set, else `%APPDATA%\Riz`. Database file: `riz.db` (app tables and LangGraph checkpoints in the same file).
- Timestamps are stored as UTC ISO-8601 strings. Dashboard days are grouped in local time.
- Backend tests never need Ollama: they use the `ScriptedModel` fake from Task 3.
- Python dependencies get a `>=` floor set to the version installed when the task adds them.
- Commit after each task with a Conventional Commit message. Never push without the user's OK.

## Review Focus

1. **Several tool calls in one model turn, with a side effect before a later approval** (for example `write_file` then `run_command`). LangGraph re-runs the whole tools node on resume, so no tool may execute twice. Pinned by `test_multiple_calls_execute_once` in Task 3.
2. **`read_file` on a huge or binary file.** Expect a truncated read with a note, or a clean "not a text file" message. Never a crash, and never a context window blown open. Pinned in Task 2.
3. **`run_command` that hangs or prints megabytes.** Expect a timeout message after 60 s and output capped at 10,000 characters. Pinned in Task 2.
4. **The user sends a message, or restarts the app, while an approval is pending.** The chat must never get stuck. The composer is disabled while a card is pending, the server rejects `send` with an error event, and the pending card comes back after a restart. Pinned in Tasks 4, 5 and 8.
5. **Ollama is not running, or the model isn't pulled.** Expect an `error` event the chat shows ("Can't reach Ollama. Is it running?"), the dashboard status shows offline, and no traceback. Pinned in Tasks 4 and 6.

**Interfaces:**
- Produces (plain functions; they return a string for the model and never raise for user-facing errors):

```python
async def tools_node(state, config):
    calls = state["messages"][-1].tool_calls
    decisions = {}
    for c in calls:                                   # interrupts first, no side effects
        if c["name"] in APPROVAL_TOOLS:
            decisions[c["id"]] = interrupt(payload_for(c))
    results = []
    for c in calls:                                   # execute once, after all decisions
        d = decisions.get(c["id"])
        if d is None:            outcome, args = "auto", c["args"]
        elif d["decision"] == "deny": outcome, args = "denied", c["args"]
        else:
            args = {**c["args"], "path": d["path"]} if d["decision"] == "pick" else c["args"]
            outcome = "allowed"
        content = DENIED if outcome == "denied" else run_tool(c["name"], args, config)
        log_tool_call(conn, chat_id(config), c["name"], args, outcome)
        results.append(ToolMessage(content, tool_call_id=c["id"], name=c["name"],
                                   additional_kwargs={"decision": outcome}))
    return {"messages": results}
```

`run_tool` dispatches to the `riz.tools` functions through the module (`tools.run_command(...)`) so the test's monkeypatch applies.

### Task 4: Chat runner (graph → UI events)

**Files:**
- Create: `backend/riz/runner.py`, `backend/tests/test_runner.py`

**Interfaces:**
- Consumes: `build_graph` and the payload/resume shapes from Task 3; `riz.db` chats and logging
- Produces `class ChatRunner(graph, conn, model_name: str)`:
  - `async def send(chat_id: str, text: str) -> AsyncIterator[dict]`: sets the chat title to the first 40 characters of `text` when the title is `"New chat"`; calls `touch_chat`
  - `async def resume(chat_id: str, decision: dict) -> AsyncIterator[dict]`
  - `async def regenerate(chat_id: str) -> AsyncIterator[dict]`: removes the last `HumanMessage` and everything after it (`RemoveMessage` through `graph.aupdate_state`), then re-sends that text
  - `async def pending(chat_id: str) -> dict | None`: the current interrupt payload, if any
  - `async def history(chat_id: str) -> list[dict]`: `{"role": "user" | "assistant", "content"}`, or `{"role": "tool", "tool", "args", "decision", "summary"}` for tool messages (args taken from the matching AI `tool_call`); AI messages with no text are skipped
- Event dicts (the WebSocket protocol from the spec): `{"type": "token", "chat_id", "text"}`, `{"type": "tool_request", "chat_id", "call_id", "tool", "args", "preview"}`, `{"type": "tool_result", "chat_id", "tool", "args", "decision", "summary"}` (`summary` = first 200 characters of the tool output), `{"type": "done", "chat_id", "stats": {"output_tokens", "tok_per_s", "total_ms"}}`, `{"type": "error", "chat_id", "message"}`
- Streams with `graph.astream(input, config, stream_mode="messages")`. AI chunks from node `"model"` become `token` events; `ToolMessage`s become `tool_result` events. Afterwards it calls `aget_state`: a pending interrupt yields a `tool_request` (no `done`), otherwise `done`.
- Thinking guard: a small stateful `ThinkFilter` with `feed(text) -> str` drops everything between `<think>` and `</think>`, including tags split across chunks (it holds back a trailing partial tag). Token events carry only the filtered text, and empty text produces no event. `history()` applies the same stripping to saved AI content.
- Model-call logging: start a clock when the stream starts and again after each tool result. The first token chunk sets `first_token_ms`. The chunk carrying `usage_metadata` ends the call: `log_model_call(...)`, then reset the clock.
- `send` while a call is pending yields exactly one `{"type": "error", ..., "message": "Answer the pending approval first."}` and does not touch the graph.
- A connection failure (`httpx.ConnectError`, or `ConnectionError` raised by the model) yields `{"type": "error", ..., "message": "Can't reach Ollama. Is it running?"}`; any other exception yields `str(exc)`.
